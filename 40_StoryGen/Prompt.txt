# マーパンの生活から物語が自然発生する観察ゲームを制作してください

既存のマーパン作品群・共通マーパン仕様を確認したうえで、新しい小規模Webゲームのプロトタイプを制作してください。

仮タイトル：

**「マーパン観察記 / Maapan Stories」**

## コンセプト

この作品では、あらかじめ物語を書きません。

マーパンたちに、

* 個体差
* 性格
* 欲求
* 記憶
* 感情
* 他のマーパンとの関係

を持たせます。

マーパンたちはそれらをもとに自律的に行動します。

すると、

**個体差 → 行動 → 出来事 → 記憶 → 関係変化 → 次の行動**

という循環が生まれます。

その結果として発生した出来事を記録し、1日の終わりに短い「物語」として読めるようにしてください。

この作品で検証したい最大の問いは、

> **「マーパンを生きさせるだけで、物語は自然に生まれるのか？」**

です。

固定シナリオを作るゲームではなく、

**小さな世界を作り、その中で起きたことを観察するゲーム**

にしてください。

# 1. 共通マーパン仕様を最優先する

まずリポジトリ内を調査し、既存の「共通マーパン」の実装・仕様・描画方法・アセット・関連ドキュメントを探してください。

新しく別デザインのキャラクターを作らないでください。

マーパンの、

* 顔
* 体型
* 表情
* 色
* 動き
* 描画方法

などは可能な限り既存の共通仕様を再利用してください。

このゲーム専用のマーパンを勝手に再定義するのではなく、

**「既存のマーパンが、この世界でも生きている」**

ようにしてください。

# 2. 最初は3匹だけ

初期プロトタイプには3匹のマーパンを登場させてください。

人数を増やすより、

**「なぜこのマーパンが今この行動をしたのか」を人間が追跡できること**

を優先します。

各マーパンには固有IDを持たせてください。

見た目が似ていても、それぞれ別個体として扱います。

# 3. 既存の遺伝子・個体値システムを調査する

リポジトリ内に、以前実装したマーパンの

* DNA
* 塩基配列
* genome
* genetics
* individual values
* traits

などに相当する仕組みが存在する場合、必ず調査してください。

存在する場合は、新しい個体値システムを別に作るのではなく、可能な限り既存システムを利用・拡張してください。

遺伝情報から例えば、

* 好奇心
* 社交性
* 警戒心
* 食欲
* 活動性
* 執着
* 協調性
* 気分の変わりやすさ

などの内部傾向を導出できるようにしてください。

重要なのは、

**色＝性格**

のような固定設定にはしないことです。

同じ色のマーパンでも個体によって性格が違うようにしてください。

# 4. マーパンはなるべく喋らない

人間のような長い会話をするキャラクターにはしないでください。

マーパンは基本的に、

* 歩く
* 近づく
* 離れる
* 見る
* 拾う
* 食べる
* 渡す
* 奪う
* 待つ
* ついていく
* 逃げる
* 一緒にいる
* 眠る

などの行動によって感情や関係を表現します。

必要なら、

「……」
「！」
「？」
「♪」

程度の簡単な表現を使用して構いません。

**行動から気持ちを想像できる余白**

を残してください。

# 5. 小さな環境を作る

最初は非常に小さなフィールドで構いません。

例えば、

* 草地
* 木
* 木の実
* 石
* 水場
* 日陰
* 寝床

程度を配置してください。

環境そのものが行動のきっかけになります。

例：

木の実が落ちる
↓
2匹のマーパンが気づく
↓
どちらが近づくか決める
↓
一匹が拾う
↓
もう一匹がそれを見る
↓
分ける / 持ち去る
↓
その出来事を双方が記憶する

# 6. 欲求

各マーパンには簡単な内部状態を持たせてください。

最低限、

* 空腹
* 疲労
* 好奇心
* 安心感
* 誰かと一緒にいたい気持ち

などを時間経過で変化させます。

性格だけで行動を決めず、

**性格 × 現在の欲求 × 周囲の状況 × 記憶 × 人間関係**

から行動を決定してください。

# 7. 記憶

マーパンは重要な出来事を記憶します。

例えば、

「赤マーパンから木の実をもらった」

「青マーパンに木の実を取られた」

「眠っていたら黄マーパンが隣に来た」

「危ないときに助けてもらった」

などです。

記憶には最低限、

* 日時
* 行為者
* 対象
* 行動
* 対象物
* 感情価
* 強度

を保存してください。

そして記憶が将来の行動に影響するようにしてください。

単純に「好感度+1」で終わらせず、

**具体的な出来事の記憶を残す**

ことを重視してください。

# 8. 人間関係

マーパン同士には関係性を持たせてください。

最低限、

* 親しさ
* 信頼
* 警戒

程度で構いません。

ただしUI上では数字だけを見せるのではなく、

「よく一緒にいる」

「少し警戒している」

「最近距離が縮まっている」

など、観察者にも理解できる表現を用意してください。

# 9. 行動理由を残す

これは非常に重要です。

各行動について内部的に、

**「なぜその行動を選んだのか」**

を記録してください。

例：

行動：
黄マーパンから離れる

理由：

* 昨日木の実を取られた記憶が強い
* 現在の警戒心が高い
* 空腹ではないため近づく必要性が低い

という形です。

後述する「神の視点」から確認できるようにしてください。

# 10. 固定イベントを極力作らない

「3日目に喧嘩する」
「5日目に仲直りする」

などの脚本は作らないでください。

出来事は可能な限り、

**マーパン自身の状態と環境の組み合わせ**

から発生させてください。

作者自身にも、

「この3匹が明日どうなるか分からない」

状態を目指します。

# 11. 時間

ゲームには、

朝
↓
昼
↓
夕方
↓
夜

の簡単な時間経過を持たせてください。

1日につき複数回、マーパンが行動します。

最初は10日程度を観察できれば十分です。

速度変更として、

×1
×2
×4
一時停止

を用意してください。

# 12. 出来事ログ

画面の端に、その日に起きたことを簡潔に表示してください。

例：

08:12　赤マーパンが木の実を見つけた

08:14　黄マーパンも木の実に気づいた

08:15　赤マーパンが木の実を拾った

08:17　黄マーパンが赤マーパンを見ている

08:20　赤マーパンが木の実を半分渡した

08:21　黄マーパンはそれを食べた

このログが後の物語生成の素材になります。

# 13. 1日の終わりに「マーパン観察記」を生成する

夜になると、その日に実際に発生したイベントログを材料として、短い文章を生成してください。

例：

## 第4日　半分の木の実

朝、赤いマーパンが木の実を見つけた。

少し遅れて、黄色いマーパンもやってきた。

赤いマーパンは木の実を拾った。

黄色いマーパンは、その場から動かなかった。

しばらくして、赤いマーパンが戻ってきた。

そして、木の実を半分置いた。

黄色いマーパンはそれを食べた。

昨日まで、二匹はあまり近くにいなかった。

その日の夜は、少しだけ近い場所で眠った。

このように、

**実際にゲーム内で発生した事実から文章を作ってください。**

起きていない出来事を勝手に追加しないでください。

# 14. 最初は生成AI APIを使わない

初期プロトタイプではOpenAI API等を必須にしないでください。

イベントログから文章を生成する簡単なNarrativeGeneratorを実装してください。

例えば、

Simulation
↓
EventLog
↓
NarrativeGenerator
↓
観察記

という構造にします。

NarrativeGeneratorは独立させ、

将来的に、

EventLog
↓
AI API
↓
本格的な小説

へ差し替えられる設計にしてください。

# 15. 同じ出来事を別のマーパン視点から読む

その日の観察記について、

* 観察者視点
* 赤マーパン視点
* 黄マーパン視点
* 青マーパン視点

を切り替えられるようにしてください。

重要なのは、

**事実そのものは変えない**

ことです。

しかし意味は変わります。

例えば、

観察者：

「赤マーパンが木の実を拾った。」

黄マーパン：

「また、赤いのが先だった。」

赤マーパン：

「木の実を見つけた。黄色いのがこちらを見ている。」

という違いです。

これによって、

**同じ世界を見ていても、それぞれ違う世界として経験している**

ことを表現してください。

# 16. 神の視点

観察ゲームとして、内部状態を見るためのデバッグ兼遊び機能を作ってください。

マーパンをタップすると、

## このマーパンについて

個体ID

遺伝情報

性格傾向

現在の欲求

現在の感情

他のマーパンとの関係

最近の記憶

重要な記憶

直前の行動

その行動を選んだ理由

を確認できるようにしてください。

通常表示では見えない、

**マーパンの頭の中を覗くモード**

という位置づけにしてください。

# 17. プレイヤーは最初は「観察者」

初期版ではプレイヤーを主人公にしないでください。

基本的にはマーパンを眺めます。

ただし、1日に数回だけ世界へ介入できるようにしてください。

例えば、

* 木の実を1個置く
* 石を置く
* 雨を降らせる
* 日向を作る
* 何もしない

程度です。

プレイヤーが直接、

「赤マーパンと黄マーパンを仲良くする」

ことはできません。

プレイヤーは環境だけを変えます。

その結果どうなるかはマーパン自身に決めさせてください。

# 18. UI

PC・スマートフォン両対応にしてください。

メイン画面ではマーパンたちが生活している様子を最も大きく表示してください。

補助UIとして、

* 日付・時間
* 再生速度
* 今日の出来事
* マーパン一覧
* 人間関係
* 観察記
* 神の視点

を確認できるようにします。

ただし管理ゲームのように数字だらけにはしないでください。

**まずマーパンを眺めることが楽しい画面**

を優先してください。

# 19. セーブ

可能であればlocalStorage等を利用して、

* 現在の日数
* 各マーパンの状態
* 記憶
* 人間関係
* 過去のイベント
* 過去の観察記

を保存してください。

ゲームを閉じても、

**その世界の歴史が残っている**

ことを重視します。

# 20. 「歴史」画面

過去の観察記を、

第1日
第2日
第3日
……

と読み返せるようにしてください。

10日遊んだ場合、

**一本の短いマーパン物語**

として最初から読み返せるようにします。

つまりこのゲームでは、

「ゲームをクリアする」

のではなく、

**遊んだ結果として、その世界だけの物語が残る**

ことを一つの成果物にします。

# 21. 将来的な拡張

初期版ですべて実装する必要はありませんが、将来的に以下を追加できる構造にしてください。

* マーパンの繁殖
* 遺伝
* 親子関係
* 世代交代
* 寿命
* 仲間
* 対立
* 群れ
* 噂
* 好きな場所
* お気に入りの物
* 長期記憶
* 忘却
* 季節
* 天候
* 食料不足
* 新しいマーパンの誕生
* 別れ
* 死
* 数十年単位の歴史
* AIによる行動決定
* AIによる本格的な小説生成

これらを追加しても現在のSimulation / Memory / Narrativeの仕組みを壊さず拡張できるようにしてください。

# 22. 今回は作り込みすぎない

今回のプロトタイプで最も重要なのはグラフィックでも機能数でもありません。

検証したいのは、

**マーパンに個体差と記憶を与えて生活させたとき、こちらが脚本を書かなくても「物語らしい何か」が生まれるのか？**

です。

したがって、

1. 3匹のマーパンが存在する
2. 個体差がある
3. 欲求がある
4. 自分で行動する
5. 出来事を覚える
6. 相手への態度が変わる
7. 過去の経験によって次の行動が変わる
8. その連鎖を観察できる
9. 1日の終わりに文章として読める

この循環を最優先で完成させてください。

# 23. 実装後に確認したいこと

READMEまたは実装報告に、

* 既存の共通マーパン仕様をどこから利用したか
* 既存の遺伝子システムを利用できたか
* マーパンの性格がどう決まるか
* 行動選択アルゴリズム
* 記憶の保存方法
* 記憶が次の行動へどう影響するか
* 人間関係の変化方法
* NarrativeGeneratorの構造
* AI APIへ差し替える場合の変更箇所
* 現在どの程度「自然発生する物語」が実現できているか

を記載してください。

最初に既存リポジトリ全体を確認し、既存の共通マーパンおよび遺伝子関連実装を再利用できるか調査してから実装を開始してください。
